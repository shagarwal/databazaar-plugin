## Bugs found by the expansion (and fixed)

The 10→71 jump surfaced **three real bugs** that v0.2's thin coverage had
hidden. This is exactly the value of broader evals.

### 1. databazaar adapter only returned 10 rows

`scripts/adapters/databazaar.py` was hitting `/sample`, which returns a
small preview. Real free listings have thousands of rows. Fix: prefer
`/download-url` when `pricing_type == "free"`. databazaar cases jumped
from min_rows ~10 → full row counts (e.g., 13,952 for World Bank tourism).

### 2. World Bank `EN.ATM.CO2E.PC` indicator was archived

The indicator returned an "Invalid format" message instead of data. The
World Bank rotates indicator codes when methodology changes. Replaced
with `EN.GHG.ALL.PC.CE.AR5` (current AR5 methodology, 195 countries).

Lesson: WB indicator codes need periodic re-validation. Future v0.4 task:
add a startup check that pings each mapped code and warns on archive.

### 3. CSV writer crashed on heterogeneous row keys

When a JSON dataset had rows with non-uniform keys (e.g., aircraft
listings where some had `useful_load`, some didn't), `csv.DictWriter`
threw `ValueError: dict contains fields not in fieldnames`. Fix: collect
the union of keys across all rows + use `extrasaction="ignore"`. This
matters more for the free-listing path because real data is messier
than samples.

## XPASS cleanup

Two cases marked `expected_fail: true` in v0.3 first run actually passed
(`prepare-edge-single-row`, `aggregate-merge-not-impl`). I removed the
`expected_fail` flags after thinking through what the cases should
actually assert:

- **single-row**: produces output cleanly today; v0.4 should add a
  row-count gate (block <10 as not-listable). Tracked as soft TODO,
  not a current failure.
- **aggregate stub**: the case is checking that aggregate refuses with
  "not yet implemented" — that's a passing refusal, not a failure.
  When aggregate lands, the case flips from `kind: refusal` →
  `kind: standard`.

The remaining xfail (`prepare-edge-empty`) is genuine: the empty CSV
should be refused but currently produces a zero-row datacard. v0.4 fix.

## What's NOT covered yet

Honesty list — these are still aspirational and shouldn't be claimed:

- **Aggregate mode** — entity resolution, schema merge, conflict
  surfacing. Stubbed only. Highest structural gap.
- **List mode** — end-to-end publish to databazaar staging. Untested.
- **Multi-source fan-out** — request that should hit 3 adapters and
  merge. Router can score, but no adapter actually merges results yet.
- **Format coverage gaps** — XLSX, Parquet, SQL dump for prepare mode.
  Spec'd, not implemented.
- **Scale** — no 100k-row stress test. Unknown if streaming is needed.
- **Recency honesty** — datacards include retrieved_at, but there's
  no case verifying stale-data flagging.
- **Provenance hash stability** — reproducibility cases pass, but
  hash equality across runs isn't asserted yet.
- **Adapter rate-limit behavior** — no test for 429 backoff.
- **Adversarial input** — no malformed CSV, broken JSON, or weird
  encoding cases yet.

## v0.4 priorities (in order of value)

1. **Aggregate mode** + multi-source merge tests + entity resolution +
   conflict surfacing. Biggest user-visible gap.
2. **List mode** end-to-end against databazaar staging. Closes the
   marketing-loop story.
3. **Empty-input and row-count gates** in prepare mode. Flips xfail
   green; small change.
4. **Adversarial fixtures**: malformed CSV, broken JSON, exotic
   encodings, deeply nested JSON.
5. **Format coverage**: XLSX (openpyxl), Parquet (pyarrow), SQL dump.
6. **Multi-source fan-out** test using a request that genuinely needs
   merging (e.g., "GDP per capita + population by country" — two WB
   indicators joined).
7. **More WB indicators** — currently 12 hand-mapped; ~hundreds available.
8. **HF row streaming** via `datasets` lib (currently metadata only).
